# BB610 MARKET — PCV3-01

## Purpose
Create a clean, isolated PRODUCT CARD v3 foundation without repairing or rewriting v1/v2.

## No-touch boundary
PCV3-01 does **not** modify:
- prices / sale prices;
- stock quantities;
- availability;
- publication state;
- orders;
- payment / delivery;
- physical image files;
- `data/catalog.master.json`;
- existing `product_card_v1` / `product_card_v2` data.

## Added
- `backend/services/product_cards_v3.py` — isolated JSON storage and validation;
- `backend/product_cards_v3_api.py` — admin-only v3 API;
- `data/product_cards_v3/` — v3 index, commerce binding map, migration manifest and frozen JSON Schema;
- `admin/product-card-v3.html` + JS/CSS — clean editor with three tabs: Контент, SKU / Фото, Комерція;
- media picker reuses the existing `/api/v1/admin/media-manager` library and stores references only;
- commerce tab is read-only and uses `commerce_map.json` bindings.

## API
- `GET /api/v1/admin/product-card-v3`
- `POST /api/v1/admin/product-card-v3`
- `GET /api/v1/admin/product-card-v3/{product_id}`
- `PUT /api/v1/admin/product-card-v3/{product_id}`
- `GET /api/v1/admin/product-card-v3/{product_id}/commerce`

There is intentionally no public storefront v3 endpoint in PCV3-01.

## Registration
To minimize risk, PCV3-01 leaves `backend/app.py` unchanged. The isolated v3 router is included by the already-mounted `product_cards_v2_api` router. No existing v2 route or storage behavior is changed.

## Frozen canonical field names
Allowed canonical names include:
- `how_it_works`
- `characteristics`
- `application`
- `sku_media.skus`
- `sku_media.media`

Forbidden aliases / legacy keys include:
- `how`
- `how_works`
- `specs`
- `applications`
- `variants`
- `sku_photo`

Commerce keys such as `price`, `stock_qty`, `availability`, `published` are forbidden in persisted PRODUCT CARD v3 JSON.

## Gate before VALAGRO-01 migration
1. Deploy PCV3-01 to a backup-protected VPS working tree.
2. Restart `bb610-market.service` and verify health.
3. Open `/admin/product-card-v3.html`.
4. Create one temporary v3 card, save, reopen, verify no data loss.
5. Add a second SKU and select an existing media-library image; confirm thumbnail.
6. Confirm prices, stock, availability, publication and orders are unchanged.
7. Delete only the temporary v3 JSON if the smoke test is complete; do not delete legacy catalog data.

Only after this gate passes should VALAGRO-01 (14 products) begin.
